# RAW 支持：第一步验证结果

验证日期：2026-10-29。**第一步基础解码验证完成，10/10 项预期检查通过。** 本次只新增独立开发探针、样片清单及实施文档，现有应用仍为 1.6.1，尚未接入 RAW 导入、预览或文件操作。

## 环境和可复现材料

- 解码器：LibRaw 0.22.3 官方 Windows x64 二进制，运行时报告 `0.22.3-Release`；编译和运行时均检查版本。
- SDK 来源：[官方固定版本 ZIP](https://www.libraw.org/data/LibRaw-0.22.3-Win64.zip)。ZIP 的本地采集 SHA-256 为 `4e2213a0b10e32199a30b9114a61376cdb40f94df861262b4a6dca659701276b`，这是下载指纹，不是发布者提供的签名。
- 本次实际加载 DLL 的 SHA-256：`2c4df36d9011267fd3ffd5c23e80d69d5f42c3d503f03ac02448f5c8a7fe0fa2`。
- 样片来自 [raw.pixls.us](https://raw.pixls.us/)，每份原片均逐项核对 CC0 声明和源站 SHA-256。来源、机型、模式及校验值保存在 [样片清单](../scripts/RawCompatibility.samples.json)。清单 `Bytes=0` 表示源站精确长度未单独取得；实际下载长度写入机器报告，不把近似 MiB 当成精确大小。
- 使用独立原生进程逐张测量；参数为全尺寸、相机白平衡、sRGB、8 位 RGB、AHD 解拜耳。没有用 RAW 内嵌 JPG 代替实际解码。
- 生成长边 1600px 的浏览预览，以及中心约 1000px、不缩放的细节裁片。六份正例预览已人工检查，未发现明显黑屏、条纹或色彩通道错乱；这不等同于与机内 JPG 的色彩精度对照。

另外三项探针检查通过：

1. 通过 LibRaw 原生回调取消，返回 `Cancelled` 和 `-100010`，未继续解拜耳。
2. 中文及带空格路径真实解码成功，JSON 路径以 UTF-8 正确往返。
3. 损坏的短文件返回明确失败（输入输出错误 `-100009`），没有崩溃或生成成功图像。

全部输入的前后 SHA-256 一致。另单独验证了“输入位于输出目录时提前拒绝且不改写输入”，以及“探针缺失时写入本轮失败报告，不能沿用上轮成功摘要”。

这些是完成输入 SHA-256 读取后的单次本机测量，文件缓存可能已经预热；耗时包含预览生成，内存为原生探针进程峰值，不包含 WPF、预览缓存或鸟种模型。不能作为所有机型、冷启动速度或整套应用内存的承诺。

## 删除 JPG 后鸟框处理的结论

不能仅凭文件同名、宽高比例相近，就把 JPG 上的框直接套到 RAW 上。本次 R7 样片已出现具体差异：

- RAW 解码输出为 **6984×4660**。
- 文件内记录的默认裁切区域为 **6960×4640**；其原始坐标起点为 `(156,84)`，相对于有效区域起点 `(144,72)` 有 `(12,12)` 偏移。
- 这证明需要考虑裁切信息；本次没有同拍外部 JPG，因此尚未确认机内 JPG 与该区域的实际对应关系，更未验证镜头校正造成的几何差异。

后续采用以下操作规则：

- 批量删除 JPG 时，只更新成员关系并标记“鸟框位置待核对”，保留鸟种结果、评级和分组；不让删除操作逐张等待 RAW 全尺寸解码及重新识别。
- 浏览当前 RAW 时按需解码。只有方向、裁切或图像配准可可靠确认时才映射旧框；否则提示“已切换 RAW，原鸟框位置待核对，鸟种结果已保留”。
- 未核对的旧框不用于 RAW 裁切识别、主体自动放大或背景排除。
- 图像级核对需要在删除前保留 JPG 小预览及几何参考；不能删除后再依赖读取原 JPG。
- 提供“重新识别本张”：成功后重建本张全部自动框和手动选区；失败或取消保留旧状态。正常定位但检出零只鸟时，另行确认是否提交空结果。

## 仍需覆盖的范围

- 同拍 JPG+RAW、竖拍、相机裁切模式和镜头校正样片：几何对齐尚未验证。
- 上表之外的机型、固件、位深、压缩模式、像素位移和高分辨率模式：不能根据品牌相同就视为通过。
- Nikon HE/HE*：当前选定解码器的样片实测不支持，需要在后续 UI 中明确提示。
- 探针已读取相机、时间、ISO、快门、光圈和焦距；曝光补偿等其他参数仍需后续统一元数据读取验证。拍摄时间没有自行推断原片时区。
- 真正接入 WPF 后，还需验证后台取消、预览缓存、解码器原生依赖打包和总进程内存。

## 运行方式

需要 Visual Studio C++ x64 构建工具。初次下载并编译验证：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-RawCompatibility.ps1 -DownloadSamples
```

SDK 和样片已缓存、探针已经编译时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-RawCompatibility.ps1 -SkipBuild
```

本地机器报告：[summary.json](../artifacts/raw-compatibility/summary.json)；各样片的 JSON、BMP 预览、细节裁片和构建日志在同一目录。SDK、原片和验证产物按现有 `.gitignore` 规则留在 `.tools`、`artifacts` 中，不随源码提交；运行脚本可以重建。
