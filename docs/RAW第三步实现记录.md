# RAW 支持：第三步实现记录

记录日期：2026-10-29。第 3 步已完成 RAW 配对导入、格式与来源显示、真实 RAW 解码预览及来源变化防护。**Release 构建零警告、零错误，含真实 RAW 与实际定位/鸟种模型的 773 项 UI 和服务检查通过。** 本步尚未发布新版本，应用版本号仍为 1.6.1；关联文件导出/删除及单张重识别仍按后续步骤完成。

## 导入与配对

- 界面的“同时读取 RAW”默认勾选，适用于添加照片和拖入照片。选择同目录、同文件名主体的 JPG 或 RAW 时，会检查该目录中的伴随原件，将一份 JPG 和一份 RAW 管理为一张逻辑照片。路径、主体名和扩展名按 Windows 大小写不敏感规则比较。
- 只配对同目录、同主体的文件，不按相似画面或相同文件名跨目录猜测关系。开启 RAW 后，不同目录的同名照片可分别保留。重复添加同一原件不会增加新的评级记录；后来补入伴随原件时，已有逻辑照片的身份、评级、分组和鸟种继续保留。
- 发现多个 JPG 候选（例如同主体的 `.jpg` 和 `.jpeg`）、多个 RAW 候选，或原件已属于多张逻辑照片时，跳过该项并明确报告冲突，不随意选择一份或合并不同评级。可整理冲突文件后重试，也可关闭该选项仅导入 JPG。
- 关闭“同时读取 RAW”时沿用原 JPG 导入和同名去重规则，不查找或关联旁边的 RAW，也不把已管理照片中的 RAW 成员解除关联。该设置影响后续导入，不更改此前工程记录。
- 有可读 JPG 时优先显示 JPG，配对的 RAW 不为了显示 JPG 而进行完整解码。首选 JPG 无法读取且有另一原件时，会报告提示并尝试可用来源；不以显示成功掩盖首选原件的错误。

导入工作在后台生成分离的新增照片和成员更新结果，完成后由界面线程应用。取消时不把未完成的更新写回已有照片。进度区报告正在检查关联文件、读取 JPG 缩略图或解码 RAW 缩略图的具体路径。

## 真实 RAW 解码与预览

解码使用固定的 LibRaw 0.22.3 Win64 SDK，并通过小型原生 ABI 桥接接入 WPF。读取元数据只执行打开和尺寸计算；需要像素时执行 `unpack`、`dcraw_process` 和 RGB 输出。对于适用的马赛克传感器执行解拜耳，使用相机白平衡和 sRGB 8 位输出，**不调用内嵌 JPEG/缩略图接口冒充 RAW 解码**。当前预览颜色用于照片筛选，不等于相机直出 JPG 或专业 RAW 编辑器的渲染风格。

RAW-only 导入会真实解码生成小缩略图，缩小发生在完整 RAW 像素处理之后。用于浏览的全尺寸 RAW 预览在选中当前照片时按需载入；相邻照片预加载会跳过 RAW，即使工程已有其尺寸。用户明确执行分组或识别时，也会按当前来源读取所需像素，这与相邻预加载分开。元数据、缩略图、前台预览和图像处理共用一个 RAW 解码通道，避免并行展开多份全尺寸 RAW。

原生解码支持 Unicode 路径和取消回调，失败、取消及成功路径都会释放原生资源。缩略图输出独立的小像素缓冲，不长期引用完整解码帧；冻结的 WPF 图像不保留原件文件锁。切换照片、清空缓存或关闭时会停止不再需要的 RAW 请求，不将迟到的结果显示为当前照片。文件内容不受支持或损坏时报告失败，不静默改用内嵌 JPG。

界面参数区显示 `JPG`、`RAW` 或 `JPG + RAW`，RAW 成员还显示实际扩展名，例如 `.NEF`；预览标题区另外显示当前像素来自 JPG 还是 RAW。EXIF 拍摄时间保留原墙钟文字，缺失时显示 `—`，不擅自补充 UTC 或相机时区。

## 来源变化与鸟框待核对

JPG 与 RAW 的有效画幅、裁切、方向或边缘可能不同。本步未建立同拍 JPG/RAW 图像配准，不依据宽高比相同自动宣布旧坐标可靠。工程恢复或成员变化导致当前来源切换时，保留逻辑照片、评级、鸟种、稳定编号和旧几何参照，并维持 `NeedsReview`。

- 待核对照片仍可以显示当前来源的图像、浏览和评级，并能查看已保存的鸟种结果。
- 明确显示“图像来源已变化，鸟框位置待核对；鸟种结果已保留”。当前图像从适应画面开始，不把旧来源的缩略图、缩放和平移当作新来源的预览。
- 未确认的旧框不叠加为当前图像位置，不控制自动放大，也不用于裁切识别或背景排除。此状态下不能追加或删除手动选区，避免混合两个坐标系。
- 自动分组可以处理当前有效图像，忽略未确认的鸟框，保持旧鸟种与框记录不变；普通批量识别对待核对照片保留原结果并给出提示。

独立的“重新识别本张”及其成功后替换所有自动/手动框的确认流程仍属于第 5 步，本步不提供绕过确认的隐式替换。

## 构建与兼容边界

开发机需安装 .NET 8 Windows Desktop SDK，以及 Visual Studio 的 C++ x64 构建工具和 x64 CRT 可再分发文件。普通 `dotnet build` 会调用 `scripts/Build-RawDecoder.ps1`：复用或下载固定 SHA-256 的官方 SDK，编译桥接，复制实际所需 DLL。SDK、构建缓存及二进制位于忽略目录 `.tools`，源码仓库保存桥接源码、脚本和许可，不提交开发缓存。

发行程序随目录携带桥接 DLL、`libraw.dll` 及三个 C++ 运行库 DLL，使用者无需安装 Visual Studio。LibRaw 采用上游提供的 CDDL 1.0 选项，未修改上游库，原始版权、许可、组件条款及对应源码地址保存在 `licenses` 和 [第三方说明](../THIRD_PARTY_NOTICES.md)。本步未生成或上传新的发行包。

工程仍写为 v2，读取 v1 时只迁移原先明确记录的 JPG，不自动关联 RAW；需要关联时由本次勾选导入触发。已发布的旧版 1.6.1 无法读取 v2。需要继续使用旧发布版的 v1 工程应保留原副本；当前开发版的手动保存和自动保存都可能写入 v2。

**当前导出/删除保护仍保留**：选定集合中含 RAW 或多成员照片时，在文件处理前拒绝整次旧式操作。全部 / 仅 JPG / 仅 RAW，以及操作结果按成员更新，留待第 4 步完成；本步不会只删除 JPG 却把仍有 RAW 的逻辑照片移走。

## 实际验证
